# Task / Result Packet

## Task

**Название:** Принятая схема упражнения во всех трёх Section editorial_v2.

**Владелец:** root — интеграция и общие документы; audit_header_navigation — только данные L01-S02; build_editorial_exercise — только данные L01-S03; review_integration_contract — независимое read-only ревью.

**Статус:** done

**Цель:** Вторые экраны L01-S01–L01-S03 используют одну принятую механику: девять последовательных вопросов, сверка с адресным пояснением каждого неверного варианта, без комментария при совпадении, и добровольное полное чтение исходной цепочки.

**Основание scope:** 30 августа 2026 года владелец явно попросил распространить принятый подход на три существующих Section новой редакционной версии. Это расширяет локальное исключение решения 28; архив и остальные 19 Section в него не входят. Схема пояснений уже принята в [предыдущей задаче](2026-08-30-editorial-option-feedback.md).

**Риски:**

- При адаптации потерять один из двух сюжетных эпизодов L01-S02 или выдать канал за гарантию безопасности.
- В L01-S03 выдать будущие условия за поступившие деньги, обещать резерв либо показать не состоявшиеся ДМС/курс/платежи.

- Удвоить канонический текст в сверке или показывать пояснение до неё/при совпадении.
- Браузерная проверка в этой сессии недоступна из-за ранее полученного явного URL-policy block; обход через другой браузер, порт, curl/CDP не допускается. Статическая проверка и локальный серверный рендер React не заменяют визуальный QA.

**План проверки:**

- В каждой из трёх Section ровно 9 звеньев в каноническом порядке, по одному точному исходному варианту и двум различным дистракторам с отдельными пояснениями (54 пояснения суммарно).
- Независимое методическое/safety-ревью новых 36 пояснений и вопросов по исходным событиям.
- Расширить существующие Stories: обе ошибки, совпадение, полное чтение, обратное редактирование и границы последовательного доступа на всех трёх наборах.
- Локальный рендер React: все правильные, обе ошибки каждого звена, смешанные ответы, чтение и отсутствие ранних пояснений; экранные маршруты и отдельные ключи состояния проверить по реализации.
- Typecheck, production build, Storybook build; относительные ссылки, `git diff --check` и `git diff --cached --check`; baseline подтверждает неизменность S01, canonical/content, archive, CSS и конфигурации.

## Result

**Итог:** Принятый формат работает на вторых экранах всех трёх существующих Section editorial_v2. L01-S02 и L01-S03 получили собственные девять вопросов и по 18 адресных пояснений; набор L01-S01 сохранён побайтно. Во всей тройке 27 вопросов, 81 вариант с уникальными id и 54 пояснения. Правильные варианты и полное чтение берут исходные абзацы из соответствующего Markdown.

**Файлы:**

- Созданы два набора и явный реестр `editorialExercises.ts`; общий компонент принимает `links`, экран выбирает набор по id, существующий владелец состояния используется во всех трёх Section.
- Расширены две существующие Stories: оба расхождения каждого вопроса на S02/S03, полное чтение без ответа для всех трёх, переходы через реальные экраны приложения и изоляция ответов между Section.
- Решение 30 и редакционный контракт явно расширяют локальное исключение; синхронизированы `AGENTS`, `README`, продуктовые/методические/safety-документы, `PROJECT_STATE` и `WORKBOARD`.
- Изменены ровно 19 файлов из объявленного write set; канонический контент, исходный S01, CSS, шапки, assets, архив, router и зависимости не менялись.

**Проверки:**

- Независимый `financial-safety-reviewer` для всех 18 новых вопросов, 36 дистракторов и 36 пояснений — PASS. Существенных замечаний нет. S02 сохраняет оба эпизода и самостоятельность Саши; S03 отделяет будущие условия от денег месяца и не приписывает состоявшиеся платежи/льготы/резерв.
- Независимое read-only ревью интеграции — PASS. Проверены выбор набора, границы текущей Section, отсутствие ранней оценки, параметризация Stories и CSS без фиксированной высоты/обрезания ответов. Это статическое ревью, не браузерная проверка.
- `node --input-type=module < /tmp/prozhito-three-section-check.mjs` — PASS: 195 рендеров React без браузера и HTTP. На Section: 22 сверки (включая оба неверных варианта каждого звена, полное совпадение и смешанные ответы), 27 состояний выбранных вариантов, 3 полных чтения, 9 границ последовательного доступа, 2 состояния с пропуском/чужими id и оба реальных экрана приложения. Канонический абзац в сверке/чтении всегда ровно один, комментарий только у выбранного расхождения. Все 22 канонические Section успешно разобраны; `6 / 22`, распределение и 48 внутренних действий подтверждены. Лог: `/tmp/prozhito-three-section-check.log`.
