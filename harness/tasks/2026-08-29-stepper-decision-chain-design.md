# Task / Result Packet

## Task

**Название:** Сблизить пошаговое упражнение с визуальным языком DecisionChain

**Владелец:** Codex

**Статус:** done

**Цель:** На изолированном маршруте `#/lab/l01-s01/stepper` представить пошаговый выбор как постепенно собираемую вертикальную цепочку, визуально и ритмически близкую к production-экрану «Решение», сохранив выбор из трёх формулировок и итоговую сверку девяти звеньев.

**Входные источники:**

- `src/components/product/DecisionChain/DecisionChain.tsx` и `.module.css` — каноническая анатомия и визуальная грамматика Path;
- `src/screens/AnalysisScreen.tsx` — production-композиция второго экрана;
- `src/screens/ExerciseLabScreen.tsx` и `.module.css` — текущая изолированная лаборатория;
- `content/sections/level-01/section-01-money-by-date.md` — канонические формулировки девяти звеньев через уже разобранный `ParsedSection`.

**Write set:**

- `harness/tasks/2026-08-29-stepper-decision-chain-design.md`;
- `src/experiments/exerciseLabContent.ts`;
- `src/screens/ExerciseLabScreen.tsx`;
- `src/screens/ExerciseLabScreen.module.css`.

**Вне scope:**

- production-компонент `DecisionChain` и экран `AnalysisScreen`;
- канонические Markdown Section, книга, продуктовые решения и методология;
- подключение упражнения как третьего production-экрана;
- изменение остальных двух lab-вариантов, сохранение ответов, аналитика, баллы, профиль, backend и публикация.

**Риски:**

- интерактивный шаг может выглядеть как форма или панель и потерять непрерывность цепочки;
- заполненное звено не должно визуально означать правильность до итоговой сверки;
- раскрытое звено может сделать цепочку слишком длинной на мобильном экране;
- смена шага должна сохранять понятный фокус и положение во viewport.

**План проверки:**

- визуально сопоставить production «Решение» и lab-stepper на `1280×900` и `390×844`;
- пройти несколько звеньев вперёд и назад, изменить ответ и завершить все девять;
- проверить семантику fieldset/radio, focus-visible, отсутствие преждевременной оценки и горизонтального скролла;
- запустить TypeScript/production-сборку и `git diff --check`.

## Result

**Итог:** Пошаговый вариант пересобран как интерактивный вертикальный Path: заполненные звенья показывают выбранную формулировку в типографике production `DecisionChain`, текущее звено раскрывает вопрос и три radio-варианта прямо внутри линии, незаполненные звенья остаются компактными узлами. Корневой lab-адрес теперь открывает выбранный пошаговый формат. Визуальные статусы не раскрывают правильность до общей сверки.

**Файлы:**

- создан `harness/tasks/2026-08-29-stepper-decision-chain-design.md`;
- в `src/experiments/exerciseLabContent.ts` пошаговый формат назначен lab-вариантом по умолчанию и обновлены заметки вариантов;
- в `src/screens/ExerciseLabScreen.tsx` боковой rail заменён собираемой девятизвенной цепочкой, добавлены нейтральные состояния, управляемый focus и возврат к звену с расхождением;
- в `src/screens/ExerciseLabScreen.module.css` интерактивный Path приведён к геометрии, marker-cycle и типографике production `DecisionChain` без импорта production CSS.

**Проверки:**

- `npm run build` — PASS; TypeScript и production-сборка успешны, остаётся общее предупреждение Vite о размере основного bundle;
- `git diff --check` и `git diff --cached --check` — PASS;
- trailing whitespace в write set — PASS;
- Browser/IAB, `1280×900`, `390×844` и `320×760` — PASS: Path остаётся вертикальным, горизонтального скролла нет, на 320 px radio-строки имеют ширину 252 px, кнопки — `252×48 px`;
- чистый initial mount в React StrictMode — PASS: `scrollY=0`, фокус остаётся на `main` и не похищается первым звеном;
- полный проход — PASS: девять ответов открывают сверку из девяти строк; до заполнения всех звеньев кнопка заблокирована и рядом видна причина;
- навигация и focus — PASS: Next/Previous/выбор узла используют единый переход, новое `fieldset` получает имя из номера, названия и вопроса; review → edit возвращает фокус к первому звену с расхождением;
- доступность состояний — PASS: `role=list` сохранён, current/filled передаются не только цветом, `aria-current` и доступные имена различают состояния, live-region один;
- свежая browser console — PASS: ошибок и предупреждений нет;
- независимые implementation, visual и copy/safety review — PASS; оставшихся findings нет;
- визуальная сверка production «Решение» и живого lab-рендера через Browser/IAB и `view_image` — PASS по marker/rail geometry, typography, open-paper composition, state semantics и responsive-модели.

**Источники и даты:**

- Локальный production-экран «Решение» L01-S01 и его исходники проверены 29 августа 2026 года.
