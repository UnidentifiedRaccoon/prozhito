# Текущие продуктовые решения

Этот журнал фиксирует действующие решения проекта «Прожито». Записи не описывают историю проекта; при изменении решения заменяйте его только через новую явно принятую запись с последствиями для канонических документов.

| № | Решение | Следствие |
|---:|---|---|
| 1 | Программа состоит из 6 уровней и 22 Section. | Распределение фиксировано: `3 / 4 / 4 / 4 / 4 / 3`. |
| 2 | Section является основной пользовательской единицей. | Пользовательской иерархии из отдельных уроков нет. |
| 3 | Каждая Section содержит ровно два экрана. | Третий экран или скрытая практика требуют нового решения. |
| 4 | Первый экран содержит полный сюжетный фрагмент. | Сокращение до пересказа, выборочных цитат или карточек запрещено. |
| 5 | Второй экран содержит полную девятизвенную цепочку. | Порядок звеньев фиксирован контрактом Section. |
| 6 | Все Section доступны сразу. | Нет блокировок и предварительных условий доступа. |
| 7 | Все Section показаны на одном общем экране и сгруппированы по уровням. | Каждый новый уровень обозначается отдельным разделительным блоком. |
| 8 | Регистрация и авторизация отсутствуют. | MVP не создаёт учётные записи и сессии. |
| 9 | Прогресс не сохраняется. | Нет viewed/completed, статусов или последней открытой позиции как серверного состояния. |
| 10 | Упражнения, проверка, рефлексия и личные ответы отложены. | Продукт не собирает ответы и не обещает обучение через практику. |
| 11 | Карта из 48 действий сохраняется только как внутренняя методическая разметка. | Действия проверяют покрытие и различия, но не отображаются как уроки продукта. |
| 12 | Техническая архитектура проекта определяется с чистого листа. | В проект входят только отдельно принятые для него архитектурные решения. |
| 13 | Технический стек будущего приложения сейчас не выбирается. | Content-first bootstrap остаётся независимым от реализации. |
| 14 | Инфраструктура и публикационный процесс создаются заново позже. | В репозитории нет deployment/cloud-конфигурации и workflow. |

## Изменение решений

Новое решение должно указать:

- какую строку этого журнала оно меняет;
- какие канонические файлы затронуты;
- меняется ли пользовательская модель, число Section или контракт двух экранов;
- какие новые риски и проверки появляются.

Тихое расхождение контента, методологии и будущей реализации с этим журналом запрещено.
