# Эксплуатация веб-пилота «Прожито»

Дата: 31 августа 2026 года. Отдельный облачный контур; GitHub Pages не заменён.

## Адреса и доступ

- [Открытый сайт](https://prozhito.ncfg.ru/) — сразу открывает редакционную версию с тремя историями, без регистрации, аккаунтов и прогресса читателя.
- [Архив всех 22 Section](https://prozhito.ncfg.ru/#/) — сохранён по явному адресу; прямые ссылки не перенаправляются.
- [Разводящая версий](https://prozhito.ncfg.ru/#/versions/) — архив из 22 Section и существующая редакционная тройка.
- [Отдельная админка](https://prozhito-editor.ncfg.ru/) — только редакторский вход.
- [Каталог в облаке](https://console.yandex.cloud/folders/b1gr37s9qf8nh0fuq1js) — `prozhito`.

Логин первого редактора — `editor`. В Lockbox этого каталога:

1. `prozhito-editor-bootstrap`, ключ `password` — начальный случайный пароль. Передавать редактору через менеджер паролей или иной согласованный защищённый канал, не через Git или публичную переписку.
2. `prozhito-editor-security`, ключ `totp` — ключ для приложения-аутентификатора: TOTP, SHA-1, 6 цифр, период 30 секунд. Служебный `rateKey` редактору не передавать.
3. Для входа нужны пароль и текущий шестизначный код. Повторное использование кода запрещено; при повторном входе дождаться следующего. Сессия — до 8 часов; выход отзывает её немедленно. После нескольких неудачных попыток — пауза 15 минут.

Значения секретов не находятся в репозитории, сборках, Docker-образе или этом документе. В БД — только scrypt-хеш пароля. Одноразовый импортёр удалён, его доступ к начальному паролю отозван; runtime этот пароль не получает.

Пилот рассчитан на одного редактора. Создание/отзыв дополнительных редакторов, смена пароля и восстановление MFA пока требуют отдельной операторской процедуры. Методисту не нужны права на облачную инфраструктуру для обычной работы.

## Редакторская работа

Выбрать уровень и Section → изменить поля → сохранить черновик → открыть предпросмотр → опубликовать с основанием и подтверждением проверки. Сохранение не меняет опубликованную версию. История позволяет вернуть **всю программу** к предыдущей публикации; это новая запись истории, старые редакции не стираются.

При конфликте правки остаются в текущем окне. Скачать копию, затем открыть актуальную редакцию; при необходимости явно удалить устаревший черновик и перенести нужный текст. Не обновлять страницу до сохранения или скачивания копии. Во время отправки формы поля заблокированы, чтобы ответ сервера не затёр более свежий ввод.

Доступны текст истории, девять звеньев, вопросы/пояснения трёх существующих упражнений, alt и адреса уже импортированных изображений. Неизвестные изображения и сломанная структура отклоняются сервером. **Загрузка новых изображений пока не подключена.** Предпросмотр использует те же компоненты, что и сайт, и не публикует черновик.

Читателю загружается единая опубликованная редакция на посещение; новая публикация подтягивается при загрузке страницы. Личные ответы и прогресс не отправляются на сервер и не записываются в хранилища браузера. Разрешённые локальные ответы трёх упражнений сохраняют прежний контракт памяти текущей Section.

## Ночное окно и расходы

- 23:55 МСК — предупреждение редактору сохранить работу.
- 00:00 — API закрывает content/admin-операции, оба интерфейса показывают технические работы.
- После drain до 00:02 — остановка на ближайшем пятиминутном запуске контроллера, обычно около 00:05.
- 07:45 — команда запуска БД; повторная сверка каждые пять минут.
- С 08:00 — открытие только после проверки готовности всех 22 Section.

Ночной status и статический экран не зависят от БД. При задержке запуска или неожиданном дневном отказе сайт показывает проверку доступности, а не старый статический контент. Уже скачанное нельзя отозвать у посетителя. Остановка не удаляет данные.

Остановка экономит вычислительные ресурсы, **но диски и резервные копии продолжают тарифицироваться**. Один хост — без высокой доступности. Месячный денежный лимит по решению владельца не установлен. Максимум приложения — два экземпляра в каждой зоне, пул каждого — три подключения. Бюджетные уведомления и внешние эксплуатационные оповещения ещё стоит согласовать.

Ноутбук не нужен для расписания: контроллер — Cloud Function с IAM-защитой, таймер — Yandex Cloud Trigger. Код и права ограничены одним кластером. При отсутствии первой копии автоматическая остановка не выполняется, пишется ошибка. При текущей операции контроллер ждёт следующего запуска.

**Проверка реальной остановки/запуска рабочего кластера днём не выполнена:** она требует отдельного разрешения на краткий простой вне согласованного окна. Запрос разрешения направлен владельцу. Не выдавать unit-проверки времени или успешный дневной no-op контроллера за состоявшийся ночной цикл.

## Резервные копии и восстановление

PostgreSQL 17, `s3-c2-m8`, один хост, 10 GiB network SSD, без публичного IP. TLS проверяется приложением. Ежедневное окно копии — 22:00 МСК, хранение — 14 дней. Обслуживание — воскресенье 07:00 МСК; для постоянной эксплуатации согласовать его с ночным выключением.

Копия после импорта `c9qgfensmmafe5c70nhm:mdbtp13sv6ng18q7eoe5` восстановлена в отдельный закрытый временный кластер. Проверены 6 уровней, 22 Section, один редактор и **полное равенство документов исходному импорту**. Затем проверочный кластер удалён, завершение операции проверено; рабочая БД и исходная копия сохранены.

В аварии сначала восстановить в **новый** кластер, проверить контент и доступы, затем явно переключить `PGHOST` новой ревизией приложения. Не восстанавливать поверх рабочего кластера и не выполнять destructive down-миграции. Ротация секретов и reset редактора требуют отдельного плана и отзыва прежних сессий.

Публикуемый контент доступен как JSON через `GET /api/v1/content`. Это не замена backup: JSON не включает историю, черновики и редакторский доступ. Канонические Markdown не перезаписываются автоматически.

## Выпуск и техническая проверка

Все ID без значений секретов — [pilot.json](../../infra/yandex-cloud/pilot.json). Всегда явно использовать профиль Yandex Cloud `default`, не переключать общий активный профиль и не менять FinPulse.

```sh
npm run build:cloud
npm run build:admin
npm --prefix server run typecheck
npm --prefix server run build:seed
python3 -m unittest discover -s infra/yandex-cloud/db-controller -p 'test_*.py'
```

Сервер собирается [Dockerfile](../../infra/yandex-cloud/Dockerfile) только из разрешённого списка файлов. `deploy-api.mjs` принимает digest из реестра проекта, передаёт ссылки на версии Lockbox и отключает ненужный доступ runtime к metadata endpoint. Credential helper для Docker хранит IAM-токен только в памяти. Начальное создание секретов повторно не запускать.

Статику выпускать в порядке: новые `assets/` → `preview.html` → `index.html` / `cloud.html`; старые хешированные assets не удалять вместе с выпуском. Шлюзы собираются `gateway-specs.mjs`. Перед выкладкой проверить совместимость API; необратимые миграции отдельно согласовать. Bootstrap после импорта не повторять.

```sh
node --experimental-strip-types infra/yandex-cloud/verify-public.mjs
node --experimental-strip-types infra/yandex-cloud/cloud-auth-smoke.mjs domain
```

Первый проверяет анонимное чтение, равенство первоначальному импорту, 50 медиа, закрытый сервер/бакет и отсутствие admin API на reader-домене. После содержательных правок редактора равенство seed намеренно перестанет проходить — не восстанавливать старый контент ради зелёного теста. Второй использует Lockbox только в памяти и проверяет вход/выход/CSRF, не меняя контент.

Terraform, GitHub OIDC / автоматический cloud-deploy, новые медиа и панель управления редакторскими аккаунтами пока не подключены. GitHub Pages workflow не менялся. Новый код не закоммичен вместе с накопленными редакционными правками; публикация кода требует отдельного Git scope. Это рабочий пилот, не высокодоступный production и не полный методический release-pass.
