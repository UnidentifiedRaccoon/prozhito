# Прожито

«Прожито» — content-first основа мобильного приложения с историями и разборами финансовых решений. Пользователь последовательно читает цельный фрагмент истории, затем видит причинный разбор решения персонажа.

В репозитории нет приложения, backend, инфраструктуры или выбранного технического стека. Здесь хранится канонический контент и контракт, достаточные для дальнейшего создания всех 22 Section.

## Программа

- 6 уровней;
- 22 Section с распределением `3 / 4 / 4 / 4 / 4 / 3`;
- одна Section — одна пользовательская единица;
- экран 1 — полный непрерывный фрагмент истории;
- экран 2 — девять звеньев: ситуация, эмоция, импульс, риск, пауза, осознание, инструмент, зрелое действие, наблюдаемый результат;
- все Section доступны сразу на общем экране и сгруппированы по уровням.

Reader объясняет, что произошло в истории и как было принято финансовое решение. Он не обещает формирование навыка, привычки или изменение поведения: в MVP нет упражнений и практики.

## Быстрый вход в проект

1. Прочитать [AGENTS.md](AGENTS.md) и [текущее состояние](harness/PROJECT_STATE.md).
2. Сверить продуктовую границу в [PRODUCT.md](docs/PRODUCT.md).
3. Открыть [каноническую историю](content/story/book.md) и [карту 22 Section](docs/CONTENT_MAP.md).
4. Для авторской работы использовать [методологию](docs/METHODOLOGY.md), [контракт Section](docs/SECTION_CONTRACT.md) и [шаблон](content/sections/level-01/section-template.md).
5. Проверить внутреннее покрытие по [карте 48 действий](content/program/competency-action-map.md).
6. Для регулируемых, меняющихся и чувствительных тем применить [SAFETY.md](docs/SAFETY.md) и skill [financial-safety-reviewer](skills/financial-safety-reviewer/SKILL.md).

Готовые эталоны:

- [Section 01 «Деньги к нужной дате»](content/sections/level-01/section-01-money-by-date.md);
- [Section 02 «Пауза перед “срочно”»](content/sections/level-01/section-02-pause-before-urgent.md).

Следующая Section намеренно не создана. Для её отдельной сборки новому агенту достаточно этого репозитория: точная граница истории, входной и выходной мосты, линза, внутренние действия, компетенции, safety-ограничения, контракт и шаблон уже находятся в перечисленных канонических файлах.

## Структура

[levels-and-sections.md](content/program/levels-and-sections.md) задаёт порядок программы. Подробные методические поля живут только в [CONTENT_MAP.md](docs/CONTENT_MAP.md); внутренние действия — только в [competency-action-map.md](content/program/competency-action-map.md). Не дублируйте эти источники в коде до отдельного решения о реализации.

## Вне MVP

Нет регистрации, авторизации, прогресса, статусов, блокировок, упражнений, проверки, рефлексии, личных ответов, пользовательских финансовых данных, аналитики, персонализации, рекомендаций, наград и геймификации.

## Базовая проверка изменений

Для content/docs-only изменения:

```sh
git diff --check
git diff --cached --check
```

Первая команда проверяет незастейдженные изменения, вторая — подготовленный к коммиту набор, включая новые файлы. Дополнительно проверьте относительные ссылки, число уровней/Section/внутренних действий, отсутствие третьего экрана и соблюдение чек-листов из [SECTION_CONTRACT.md](docs/SECTION_CONTRACT.md).
