# Прожито

«Прожито» — content-first основа мобильного приложения с историями и разборами финансовых решений. Пользователь читает цельный фрагмент истории, затем видит причинный разбор решения персонажа.

В репозитории также есть статическая демоверсия всех шести уровней. Она показывает 22 готовые Section без backend, базы данных, авторизации, API, сетевого хранения и аналитики. Стек демо не определяет архитектуру будущего полного приложения.

## Демоверсия для просмотра

- [Выбор версии](https://unidentifiedraccoon.github.io/prozhito/#/versions/).
- [Архивная версия — все 22 истории](https://unidentifiedraccoon.github.io/prozhito/#/).
- [Редакционная версия — три истории первой главы](https://unidentifiedraccoon.github.io/prozhito/#/editorial-v2/).

Редакционная версия включает добровольное упражнение и разбор, одинаковые по размеру обложки и пару иллюстраций «сюжет / деталь» для каждой из трёх Section. Для просмотра не нужны установка или вход в аккаунт.

## Локальная демоверсия

Демо использует Vite, React, TypeScript и `react-markdown`. Канонический пользовательский текст не скопирован в TypeScript: клиент импортирует 22 Markdown-файла Section и выделяет из каждого название, историю и девятизвенную цепочку экрана «Решение». Общий manifest задаёт только программный порядок, уровни и пути к файлам.

Требуется Node.js `^20.19.0` или `>=22.12.0`.

Установка и запуск:

```sh
npm install
npm run dev
```

Vite напечатает локальный URL в терминале. Приложение использует hash-навигацию, поэтому прямые ссылки на экраны «История» и «Решение» работают без серверных redirect rules.

Проверка типов и production-сборка:

```sh
npm run typecheck
npm run build
```

Локальная проверка production-сборки:

```sh
npm run preview
```

Локальная мастерская компонентов:

```sh
npm run storybook
```

Production-сборка Storybook для проверки:

```sh
npm run build-storybook
```

Storybook не публикуется и не подключён к внешним visual-regression сервисам. Дизайн-договорённости, токены и правила добавления компонентов зафиксированы в [DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md).

Сборка появляется в `dist/`. Для GitHub Pages задан `base: "/prozhito/"`; hash-навигация сохраняет прямые ссылки на экраны без серверных redirect rules. Существующий GitHub Actions workflow после push в `main` устанавливает зависимости, проверяет и собирает демо, затем публикует `dist/` в GitHub Pages. Storybook и рабочие документы в артефакт сайта не входят; исходный репозиторий публичный.

## Программа

- 6 уровней;
- 22 Section с распределением `3 / 4 / 4 / 4 / 4 / 3`;
- одна Section — одна пользовательская единица;
- экран 1 — полный непрерывный фрагмент истории;
- экран 2 «Решение» — девять звеньев: ситуация, эмоция, импульс, пауза, риск, осознание, инструмент, действие, результат;
- все Section доступны сразу на общем экране и сгруппированы по уровням.

Reader объясняет, что произошло в истории и как было принято финансовое решение. Он не обещает формирование навыка, привычки или изменение поведения. В базовой архивной версии упражнений нет; для вторых экранов `editorial_v2 / L01-S01–L01-S03` принято [расширение исключения — решение 30](docs/DECISIONS.md#упражнения-трёх-section-30): добровольное восстановление девяти звеньев, сверка и полный разбор без упражнения на одном адресе каждой Section. При расхождении поясняется именно выбранный вариант, при совпадении показывается только полный исходный абзац. Ответы существуют лишь в памяти текущей Section, без хранения прогресса или переноса между Section; архив, остальные Section и канонические тексты не меняются.

## Быстрый вход в проект

1. Прочитать [AGENTS.md](AGENTS.md) и [текущее состояние](harness/PROJECT_STATE.md).
2. Сверить продуктовую границу в [PRODUCT.md](docs/PRODUCT.md).
3. Открыть [каноническую историю](content/story/book.md) и [карту 22 Section](docs/CONTENT_MAP.md).
4. Для авторской работы использовать [методологию](docs/METHODOLOGY.md), [контракт Section](docs/SECTION_CONTRACT.md) и [шаблон](content/sections/level-01/section-template.md).
5. Проверить внутреннее покрытие по [карте 48 действий](content/program/competency-action-map.md).
6. Для регулируемых, меняющихся и чувствительных тем применить [SAFETY.md](docs/SAFETY.md) и skill [financial-safety-reviewer](skills/financial-safety-reviewer/SKILL.md).

Готовые эталоны первого уровня:

- [Section 01 «Деньги к нужной дате»](content/sections/level-01/section-01-money-by-date.md);
- [Section 02 «Пауза перед “срочно”»](content/sections/level-01/section-02-pause-before-urgent.md);
- [Section 03 «Черновик вместо памяти»](content/sections/level-01/section-03-draft-instead-of-memory.md).

## Вне MVP

Нет регистрации, авторизации, сохранённого прогресса, статусов прохождения, блокировок Section, рефлексии, личных ответов, пользовательских финансовых данных, аналитики, персонализации, рекомендаций, наград и геймификации. Упражнение и сверка допускаются только в указанном исключении для `editorial_v2 / L01-S01–L01-S03`; [полный контракт](docs/EDITORIAL_V2.md#упражнения-первого-уровня).

## Базовая проверка изменений

Для content/docs-only изменения:

```sh
git diff --check
git diff --cached --check
```

Первая команда проверяет незастейдженные изменения, вторая — подготовленный к коммиту набор, включая новые файлы. Дополнительно проверьте относительные ссылки, число уровней/Section/внутренних действий, отсутствие третьего экрана и соблюдение чек-листов из [SECTION_CONTRACT.md](docs/SECTION_CONTRACT.md).

Для демо дополнительно выполняются `npm run typecheck` и `npm run build`. При изменении дизайн-системы также выполняется `npm run build-storybook`. Общий парсер Markdown запускается и в клиенте, и перед Vite build; нарушение контракта двух экранов или девяти звеньев останавливает сборку с указанием файла и причины.
